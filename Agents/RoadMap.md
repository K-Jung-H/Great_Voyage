# RoadMap

기준일: 2026-10-18 (Asia/Seoul). 상태: 1단계 사용자 테스트 통과. codex/game-time-save에서 2단계 구현·컴파일 및 사용자 직접 테스트 통과. 2단계 완료 및 커밋 61873c2. 3단계 구현·컴파일 확인 및 공통 Cell 보완 후 사용자 테스트 통과·커밋 e3a6ba6. 4단계 수동 항해 구현·컴파일/참조 확인 및 사용자 직접 테스트 통과, 1~4단계 main 통합/푸시 8276144. 5단계 선원 업무·생활 구현·컴파일/참조 확인 완료, 사용자 직접 테스트 통과. 이벤트 시작 체크포인트는 기존 8단계에서 구현한다.
이 문서는 구현 순서 제안이며 구현 실행·브랜치 생성·파일 생성·기능 테스트의 일괄 승인이 아니다. 요구사항은 [GameDesign](GameDesign.md), 확정 기술 구조는 [Architecture](Architecture.md)를 따른다.

## 진행 방식과 구조 전제

- 아래 1~9단계에서 각 시스템의 대표 기능을 연결한 뒤, 10단계에서 나머지 기능·콘텐츠를 확장한다. 대표 기능만 있는 상태를 해당 시스템의 최종 완성으로 표시하지 않는다.
- 단계마다 관련 컴파일 상태를 확인하고, 사용자 테스트 또는 명시적으로 승인된 기능 테스트 결과를 확인한 후 다음 단계로 진행한다. 아래 완료 목표는 미래 수용 조건이며 테스트 수행·통과 기록이 아니다.
- 새 시스템으로 전환할 때 Rules에 따라 브랜치를 제안한다. 브랜치 생성·전환·커밋·푸시는 자동 실행하지 않는다.
- 초기 장면의 고정 배치·임시 자산·소수 콘텐츠는 개발용 구성이다. 새 게임의 무작위 시작 항구·선원 0명 등 최종 규칙을 변경하지 않는다.
- 최초 조작 캐릭터는 플레이어 Prefab이다. Rigidbody2D/Collider2D, 입력·이동·상호작용 스크립트 등 필요한 Unity 컴포넌트부터 구성하는 안을 제안한다. PersonActor/PersonMotor나 인물 상속 트리를 선행 구축하지 않는다. 선원 도입 시 실제 공통 이동·표현만 공유한다.
- 함선은 층별 외형 Prefab과 배치 가능 영역 데이터, 시설 Prefab의 조합을 제안한다. 격자는 점유·통행 판단용이며 Tilemap 사용을 전제하지 않는다. 확정되지 않은 물리 이동 방식·그리드 크기·AI 경로 탐색 방식은 해당 단계에서 구체화한다.
- 함선의 세계 지도상 위치와 인물의 선내 층·지역 위치는 별도로 관리한다. 화면 전환으로 게임 상태를 삭제하지 않는다. 다른 층의 시뮬레이션은 렌더링·Collider 활성 여부와 분리한다.
- 시설 종류·상품 규격 등 정의 데이터와 내구도·재고·계약 등 현재 상태를 분리한다. 안정 ID와 저장은 2단계부터 도입하고 각 시스템 추가 때 함께 확장한다. 마지막에 저장을 덧붙이지 않는다.
- UI는 행동 요청과 표시를 담당하고, 계약 정산·재고 이전·전투 결과 등 규칙 처리는 화면 코드와 분리한다. 모든 종류를 위한 거대한 공통 관리자부터 만들지 않는다.
- 미해결 참조 7개는 사용자 지시에 따라 무시하며 선행 조건으로 삼지 않는다. 배포 설정은 게임 개발 완료 후 별도 작업으로 둔다.

## 0. 준비 상태

- 완료한 준비: 최종 기획 전체 반영, 도안·예시·그래픽 26장과 원본 md 보관, Unity 프로젝트 및 기존 CLI/Pipeline 연결 확인.
- 남은 것은 아래 각 구현의 구체 설계와 실행이다. 준비 완료가 게임 기능 검증 완료를 뜻하지 않는다.

## 1. 플레이어 이동과 첫 상호작용

상태: 구현·컴파일 확인 완료, 사용자 직접 조작 테스트 통과. 조작감 보완과 객체별 계층 설계는 후속 구조 구체화 때 진행한다.

현재: 구현은 codex/player-interaction에 분리되어 있으며 main에는 포함하지 않는다.

- 선행: 0단계.
- 만드는 대상: 작은 선장실 바닥·벽, 플레이어 Prefab 1개, 항해일지 책상 Prefab 1개, 카메라, 최소 일지 패널.
- 구현 순서: 플레이어 이동·벽 충돌 → 카메라 → 책상 접근 탐지·행동 안내 → 사용 입력 → 패널 열기·닫기.
- 첫 상호작용 대상은 사물인 책상이다. 특수 타일 배치와 선원 AI는 아직 만들지 않는다. 책상 조작은 이후 실제 항해일지의 진입점으로 재사용한다.
- 입력/이동/상호작용 책임을 작은 컴포넌트로 나눈다. 인물의 모든 기능을 조종하는 Actor 관리자는 만들지 않는다.
- 완료 목표: 플레이어가 벽을 통과하지 않고 책상에 접근해 창을 열고 닫는다. UI 조작 중 이동 입력이 잘못 전달되지 않는다.
- 제외: 전체 지도·일지 기록, 선원, 항해, 시설 편집. 패널은 기능 연결용 최소 화면이며 완성된 일지가 아니다.

## 2. 게임 시간·정지·상태·저장

현재: 구현·컴파일 및 씬 참조 확인 완료, 사용자 직접 기능 테스트 통과(2026-10-19). 에이전트 기능 테스트는 미실행. 2단계 범위는 완료했다. 이벤트 시작 체크포인트와 사건 난수 재현은 8단계 범위로 구체화하며 전체 단계 순서는 유지한다. 다음 단계는 3단계지만 이번 문서 정리에서 자동 착수하지 않는다.

- 선행: 1단계의 실제 조작·패널.
- 만드는 대상: 게임 세션 상태, 하루 10분 시간 진행, 날짜 표시, 정지 사유 관리, 저장 데이터와 읽기/쓰기 처리.
- 구현 순서: 날짜·시간 → 일지 UI의 정지 사유 등록/해제 → 겹친 창의 정지 유지 → 플레이어 ID·공간·위치와 시간 저장 → 정상 종료 후 복원.
- 게임 진행 모드와 UI 정지 사유를 분리한다. 모든 UI 종류를 게임 모드 하나씩으로 늘리지 않는다. 저장 버전·안정 ID·원자적 쓰기의 최소 구조를 만든다.
- 완료 목표: 창 하나를 닫아도 다른 정지 사유가 남으면 재개되지 않는다. 저장·재개 후 같은 위치와 시간으로 돌아온다.
- 제외: 아직 없는 계약·전투 상태. 이후 각 단계에서 해당 상태와 중복 처리 방지를 추가한다.
- 관련 수용 기준: A02, A27 중 정상 종료·복원 부분.

## 3. 함선의 층·시설 배치 구조

현재: codex/ship-floors-facilities에서 구현·컴파일·직렬화 참조 확인 및 공통 Cell 보완 완료. 사용자 직접 테스트 통과 보고(2026-10-19)로 3단계 대표 기능 완료. 에이전트 추가 기능 테스트 없음. 4단계는 사용자 요청 전 착수하지 않는다.

- 선행: 1~2단계.
- 만드는 대상: 개발용 2층 함선 1개, 연결 계단, 층별 배치 영역, 침대 시설 1종. 2층은 개발 구성이지 모든 함선의 층수 제한이 아니다.
- 구현 순서: 층별 외형·경계 → 계단 이동 → 인물 지역 위치 유지 → 시설 정의/인스턴스 분리 → 침대 2×1 점유·중복·영역 밖 배치 판정 → 이동 가능 영역·시설 접근 위치 산출.
- 시설 배치는 먼저 개발용 고정 데이터로 구성한다. 임의 장소에서 사용 가능한 편집 UI를 만들지 않는다.
- 완료 목표: 층 전환 시 해당 층만 보이고 위치·시설 상태는 유지된다. 시설이 겹치거나 배 밖에 배치되지 않으며 접근할 수 있는 위치가 정의된다.
- 제외: 모든 시설 종류, 실제 조선소 편집 화면, 선원 생활.
- 관련 수용 기준: A03의 공간·상태 부분. 선원 시뮬레이션은 5단계에서 연결.

## 4. 수동 항해와 출입항

현재: 승인된 codex/manual-navigation에서 방향타·승하선·항구2개·세계 좌표 항해·자동 입항·완료 ID·HUD·저장 v3 연결 완료. 컴파일 및 참조 확인 완료, 사용자 직접 테스트 통과. 에이전트 추가 기능 테스트 없음. 5단계 미착수.

- 선행: 함선·시간·저장·상호작용.
- 만드는 대상: 방향타, 선착장, 개발용 가상 항구 2곳, 고정 해역 데이터, 항해 위치·방향·속도, 기본 HUD.
- 구현 순서: 선착장↔함선 이동 → 방향타 사용 → 선내 위치와 별도의 세계 좌표 이동 → 항구 범위 진입·자동 입항 → 범위 밖 이탈 후 재입항 → 항해 완료 1회 통지.
- 항해 결과에 안정 ID를 부여해 나중에 계약 횟수 차감이 중복되지 않게 연결한다. 이후 단계의 계약을 여기서 미리 구현하지 않는다.
- 완료 목표: 선원 없이 직접 조타해 출항하고 같은/다른 항구로 입항한다. 층 이동으로 함선의 위치가 바뀌거나 항해 횟수가 중복 증가하지 않는다.
- 제외: 자동 조타, 세계 무작위 생성, 바람 추진 시스템, 완성된 항구 콘텐츠.
- 관련 수용 기준: A04. A15의 출항 제한은 시설·선원 연결 후 완성한다.

## 5. 선원 1명과 시설 업무·생활

현재: 승인된 codex/crew-work-life에서 상태/경로/수리 선점·중단/식사·취침/화면 밖 갱신/저장 v6 구현. 목적지 중심 저장·상호 밀림·작업 복귀·배회·개발 재준비 보완. Nav 긴 주기 재탐색+Context steering+연속 물리 이동 보완 완료. CrewPrototype 개발 씬과 별도 저장 슬롯 구성, 컴파일·참조 확인 완료. 사용자 직접 테스트 통과(2026-10-19). 에이전트 기능 테스트 미실행. 6단계 준비 중.

- 선행: 함선의 공간·시설·시간·항해.
- 만드는 대상: 개발용 선원 Prefab 1개, 선원 상태, 이동 경로, 업무 후보·자격·선점·중단 처리, 수리 가능한 시설 1개, 수리 자재·식량 수량, 침대.
- 구현 순서: 목적지 이동 → 자격 있는 정비 선원의 수리 작업 → 작업 선점/해제 → 식사·취침 우선 전환 → 일감이 없을 때 휴식 → 화면 밖 층에서도 상태 진행.
- UI 상호작용과 AI 업무는 분리한다. 선원은 수리 UI를 열지 않고 작업 위치에서 수리 규칙을 수행한다. 이동 공유가 실제 필요한 시점에 플레이어와의 공통 부분을 추출한다.
- 선원 2명을 개발 구성에 추가해 같은 시설을 중복 선점하지 않는 조건을 확인 대상으로 삼는다. 정식 새 게임은 여전히 선원 0명이다.
- 완료 목표: 선원이 자격·필요 자재·접근 가능 여부를 따져 일하고, 욕구·중단·시설 제거 시 선점을 해제한다. 다른 층에서도 생활이 멈추지 않는다. 굶주림만으로 사망하지 않는다.
- 제외: 모든 직업·특기·시설 종류. 실제 고용은 다음 단계에서 연결.
- 관련 수용 기준: A03, A07, A08, A16의 선상 부분 수리 제한.

## 6. 항구 거래·고용·계약의 첫 순환

- 선행: 인물 ID·재고·항해 완료·저장.
- 만드는 대상: 주점 고용 창, 구매 상인 1명, 판매 대행인 1명, 상품 1종, 선원 후보 1명, 계약 상태, 금화·미지급금·명성.
- 구현 순서: 구매/판매와 재고 이전 → N회 계약 고용 → 선불/후불 선택 → 항해 완료 ID에 따른 횟수 반영 → 만료·지급 → 출항 전 미정산 처리·강제 매각·명성 판정.
- 초기부터 선불 전액/후불 만료 전액 규칙을 지킨다. 먼저 항해별 분할 지급을 만들고 나중에 고치는 방식은 사용하지 않는다.
- 완료 목표: 거래해 선원을 고용하고 항해 후 정산한다. 저장·재개로 금화·상품·계약 차감이 중복되지 않는다. 채무 처리와 게임 오버/계속하기 제한이 연결된다.
- 제외: 전체 상품·후보 목록, 모든 시장 변동 요인, 완성된 항구 지도.
- 관련 수용 기준: A09~A12, A26의 거래·계약 부분, A27.

## 7. 항해일지·자동 조타·취침

- 선행: 실제 항해 경로, 선원 업무·자격, 시간 정지·저장.
- 만드는 대상: 첫 책상의 일지 패널 확장, 현재 위치 지도, 이동 경로 기록/확정, 계획선, 기록 레이어, 메모, 항해사 업무, 취침·불침번 진행.
- 구현 순서: 실제 이동 샘플 → 사용자가 일지에 기록 → 계획선 입력 → 자격 있는 항해사의 조타 → 취침 중 시간/항해 진행 → 입항 시점 중단.
- 이벤트 처리 전체는 다음 단계에서 추가하지만 사건 시점에서 멈추고 사건 정보를 기록하는 연결 지점은 마련한다. 다음 단계까지 사건 연계 완료로 표시하지 않는다.
- 완료 목표: 계획선만 그려서는 자동 이동하지 않는다. 항해사가 있어야 자동 조타하며 취침 중에도 정해진 업무가 유지된다. 기록 이월·공백 규칙이 보존된다.
- 관련 수용 기준: A05~A06, A21~A24(사건 연계는 8단계에서 완성).

## 8. 이벤트 진행과 결과 저장

- 선행: 항해·시간·일지·시설·재고.
- 만드는 대상: 이벤트 ID·발생 조건·시드/난수 진행 정보·시작 체크포인트·선택·종료·결과 적용 기록, 첫 사건으로 폭풍우 1종.
- 구현 순서: 저장된 난수 진행 정보로 사건 판정 → 이벤트 식별자·난수 조건·시작 게임 상태 확정 및 자동 저장 → 취침 중단/이벤트 진행 → 종료 결과와 처리 완료 상태 저장.
- 이벤트 중 저장·종료 요청은 시작 체크포인트를 보존한다. 불러오기는 해당 사건의 시작부터 재개하며 현재 진행 중 상태를 시작 스냅샷과 공유해 변형하지 않는다.
- SaveService의 파일 쓰기 기능 위에 이벤트 유무에 따른 저장 대상 선택 정책을 연결한다. 사건 이전의 발생 판정과 사건 내부 난수를 관리하고, 시드/호출 순서 또는 확정 추첨값을 보존해 재접속으로 재추첨하지 않는다. 완전한 물리·프레임 결정론은 요구하지 않는다.
- 폭풍의 구체 수치는 임시 설정값으로 관리한다. 이벤트 편집이 허용되는 시점과 편집 중 정지를 연결하며 자유로운 항해 중 편집으로 확대하지 않는다.
- 완료 목표: 사건 중 저장·종료 후 재개하면 같은 사건 시작 상태·난수 조건으로 돌아온다. 동일 조건의 재접속으로 사건을 피하거나 재추첨하지 못한다. 종료 결과는 중복 반영되지 않고 미기록 사건의 취침 후 소실 규칙이 유지된다.
- 제외: 이벤트 종류 대량 추가, 전투.
- 관련 수용 기준: A23~A24, A26, A17.

## 9. 관전 전투·포로 처리

- 선행: 선원·무기/재고·계약·이벤트 결과. 8단계의 이벤트 시작 체크포인트를 전투에도 적용한다.
- 만드는 대상: 해적 사건 1종, 적 인물, 무기고, 근접 무기와 총의 최소 공격 처리, 체력·공격 대기 표시, 관전 UI, 감옥과 시청 인계.
- 구현 순서: 무장/무기고 경유 → 양측 자동 전투 → 승패 → 조건별 약탈 → 사망·계약 파기 → 생존 포로 수용·식량·다음 항해 유지 → 1회 인계 보상.
- 플레이어 직접 전투·스킬 명령을 넣지 않는다. 무선원/아군 전원 사망 패배와 플레이어 생존을 처음부터 처리한다.
- 완료 목표: 해적 사건의 시작부터 전투 종료·약탈·포로 인계·저장 복원까지 한 흐름으로 연결된다. 재실행으로 결과를 중복 지급하지 않는다.
- 관련 수용 기준: A14의 사망·포획 부분, A18~A20, A26.
- 이 단계까지 주요 시스템 골격을 연결한다. 기본 게임 순환은 고용→보급→항해→사건→입항→정산이다.

## 10. 기획 전체 기능과 콘텐츠 확장

선행: 1~9단계의 대표 기능이 확인된 상태. 아래 순서대로 기존 구조를 확장하며 새 기반을 중복 구축하지 않는다.

| 순서 | 구현 범위 | 목표 |
|---|---|---|
| 10-1 시설·조선소 | 침대·대포·화물·감옥·화장실·무기고·망루·방향타·일지 등 기획 대상, 설치 제한·내구도·완전 파손·수리, 허용된 편집, 함선 매매·교체·수용량 이전 | 필수 시설과 출항 제한, 선상/조선소 수리 차이, 함선 교체 후 상태 보존 완성 |
| 10-2 선원·고용 | 능력·특기·경력·소망·행복도·신뢰도, 주 업무와 일반/특별 업무, 협상·유료 정보/후보, 게시판 재고용 | 자격·계약·직전 항구 동행 기록이 일관된 고용·운영 완성 |
| 10-3 항구·경제 | D08~D12 구역, 상품 분류, 일별 가격·재고·수요와 날씨/계절/사건 요인, 주민 요청·시청 퀘스트, 지역 평판과 전체 명성 | UI뿐 아니라 구매·판매·요청 만료·보상·항구 간 경제 순환 완성 |

- 관련 수용 기준: A01, A13~A17, A25 및 이전 단계의 남은 예외. 전체 A01~A27을 대상으로 기능 대응 누락을 점검한다.

## 11. PC 완성도 정리

- 선행: 기획 기능 전체 연결.
- 범위: 임시 자산을 D/G 기준의 최종 외형으로 교체, Head/Body/Hand 유닛 표현, UI·대사 일러스트·애니메이션·오디오, 해상도 대응, 조작 안내, 밸런스, 장기 진행·저장 일관성 및 필요한 성능 개선.
- 그래픽 기준은 1단계부터 준수하고 이 단계에서 최종 자산과 시각 완성도를 마무리한다. 예시 이미지의 미승인 버튼·기능을 추가하지 않는다.
- 완료 목표: 사용자 또는 승인된 범위의 검증에서 A01~A28을 충족하고 여러 항해·계약·사건·저장 순환이 유지된다. 검증 범위와 미실시 항목을 별도로 기록한다.
- 자동으로 전체 테스트·장시간 테스트·배포를 실행하지 않는다.

## 12. 모바일 입력

- 선행: PC 전체 흐름 완성.
- 범위: 초기 UI에 확보한 조작 영역에 가상 조이스틱·상호작용 버튼 연결, 터치 지도·목록·패널, 화면 크기·안전 영역 대응.
- 완료 목표: PC와 같은 게임 행동·시간·계약·전투 규칙을 모바일 입력으로 수행한다. 게임 규칙을 모바일용으로 별도 복제하지 않는다.
- 실제 기기 검증은 목적·범위를 정해 승인된 경우 수행한다. 배포 설정은 포함하지 않는다.

## 범위 밖의 후속 작업

- 사용자 세계 커스텀·무작위 세계 생성은 기획상 향후 확장이다. 초기 고정 가상 세계와 분리한다.
- 스토어·배포·출시 설정은 게임 개발 완료 후 별도로 다룬다.

## 다음 구현 요청의 구체 범위

첫 요청 묶음은 1단계: 플레이어 1명, 선장실 공간, 책상 1개, 이동·충돌·카메라·상호작용·최소 일지 패널이다. 구현 전 실제 생성할 스크립트·Prefab·Scene과 브랜치를 제시하고 Rules의 승인 범위를 따른다. 이후 2단계의 시간·중첩 정지·저장으로 연결한다.
