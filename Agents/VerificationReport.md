# S1~S7 통합 검증 결과 — 2026-10-20

기준: main `739df4a`. 사용자 ‘테스트 진행해’ 승인에 따라 Unity6000.6.4f1의 실제 Game Scene Play 및 별도 상태/저장 자동화를 실행했다. 커밋·푸시·8단계 작업은 하지 않았다. 이전 문서의 기능 미검증 표기는 본 보고서에 명시한 범위에서 갱신한다.

## 결론

**검사한 대표 기능·경계는 통과했다. 실제 결함1건을 발견해 수정하고 재검증했다.** Selectable의 반복 Play 진입/종료 IndexOutOfRange는 이번 실행 구간에서0건이다. 기존 사용자 개발 저장은 테스트 전에2파일(json/bak)을 백업하고, 종료 후 원본 SHA256 일치를 확인해 복구했다. 테스트 산출물은 ignored `Temp/Verification`에 보관했다.

본 검증은 Unity Test Runner의 정식 테스트 어셈블리가 아니라 Unity CLI의 일회성 `run_script` 자동화다. 실제 GameComposition/GameRuntime/Controller·Rigidbody·입력·저장 코드를 사용했다. 화면 서비스/포털의 상당수는 직접 바인딩된 명령·Button.onClick으로 호출했으며 전체 경로를 마우스 좌표 클릭/도보 이동으로 순회한 테스트와 구별한다. 키보드 이동·벽·E/ESC·W/D 조타는 Input System 입력을 전달해 실제 프레임에서 확인했다.

## 발견 결함과 수정

- 재현: 선장실 플레이어를 책상 접근점 부근 `(2,-1.05)`에 두면 접근점 `(2,-.75)`은1.25Cell 범위 안이지만, 책상 고체 Collider의 하단은 `.85`라 검색 OverlapCircle에 포함되지 않는다. 따라서 목표가 없고 E 입력으로 일지를 열 수 없었다.
- 수정: `Assets/Prefabs/World/StarterShipWorld.prefab` 내부 JournalDesk의 기존 InteractionPoint에 반지름 `.2`인 검색용 CircleCollider2D Trigger를 추가했다. 원본 JournalDesk Prefab·고체/논리 차단·접근 좌표·게임 규칙은 바꾸지 않았다. 다른 WorldInteraction 접근점과 같은 검색 구조다.
- 재검증: Play에서 거리/차폐 조회가 JournalDesk를 반환하고 E로 Journal 열기, Close 버튼·입력/시간 복귀 통과. 새 Game Scene 정적 검사도 통과했다.

## 테스트 도구/환경에서 교정한 사항

1. Editor가 비활성이며 Run In Background가 꺼진 초기 검사에서는 프레임이 진행되지 않아 레이아웃/이동/시간 복귀를 잘못 실패로 판정했다. 테스트 중에만 런타임 runInBackground를 켜고 Game View를 활성화하여 재검증했다. PlayerSettings를 변경하지 않았다.
2. 브랜치 반영 이후 Editor가 밀린 자산 재임포트/강제 재컴파일를 처리하며 Play 중 비직렬화 GameRuntime이 소실된 구간이 있었다. 이를 정상 세션 검증으로 사용하지 않고 Play를 종료·재진입한 뒤 계속했다. Play 중 스크립트 재컴파일/핫 리로드의 상태 보존은 보장한 범위가 아니다.
3. 물리 표현이 연결된 항해사의 초기4초를 수동 도메인 tick만으로 진행하면 Rigidbody 프레임이 진행되지 않는다. 최초 시간 한도 실패를 실제 프레임 기반의 방향타 도착/회전 검증으로 교정했다. 이미 만료된 N=1 항해사를 활성 명단으로 가정한 도구도 현재 항구에서 재고용한 후보로 교정했다.
4. 손상 JSON은 InvalidDataException뿐 아니라 JsonUtility.ArgumentException으로도 거부되며 이를 정상 거부로 판정했다. 기존 입항 정책은 진입 경계까지의 소비 시간만 반영한 뒤 항구 중심에 정박시키므로, 위치가 경계에 남아야 한다는 초기 기대를 기존 규칙에 맞게 교정했다. 두 항목을 게임 결함으로 수정하지 않았다.

초기 실패 기록/Console 이력은 지우지 않았다. 마지막 결과와 도구·환경 원인을 구별한다. 실행 구간 Editor.log에서 새 IndexOutOfRangeException/Game initialization stopped/NullReferenceException 로그는 각각0건이었다. Pipeline 요청의 일시적 연결 오류·JSON 객체 표시 오류는 도구 실행 문제로 기록했다.

## 저장 보호 및 종료 상태

- 실제 초기화 도구의 ResetSlot 데이터 경로를 사용자 승인 범위에서 호출해 json/tmp/bak 백업·초기화를 검증했다. 네이티브 확인 대화상자의 마우스 조작/취소는 검증하지 않았다.
- 원본2파일은 `Temp/Verification/OriginalSave`, 최초 존재/부재3슬롯 정보와 SHA256은 original-save.json에 보관했다. 종료 후 해시 대조 복구, 원래 없던 tmp는 없는 상태로 복구했다. 사용자 프로토타입·Player 저장은 대상으로 삼지 않았다.
- 마지막 테스트 저장은 `Temp/Verification/TestSaveFinal`로 별도 보관했다. 독립 `reconstruction-verification-*` 슬롯과 합성 가져오기 테스트 파일은 정확한 파일 경로를 확인해 제거했다. 기존 가져오기 원본은 사용하지 않았다.
- 최종 Editor는 Game Scene clean/stopped. 컴파일 up_to_date/failed=false/errors=[]/warnings=[]. 정적 검사915객체/2705컴포넌트/20452참조/UI키457·접근점26·7구역 오류0/경고0. 증가1컴포넌트는 위 책상 Trigger다.
